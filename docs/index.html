svm32

A complete 32-bit computing platform

svm32 (pronounced 'swim 32') is a highly experimental, fun-filled, hobby project where I attempt to build a complete 32-bit computing platform from scratch!

I have always been fascinated by computer architecture, assembly programming, compilers, and operating system concepts. In my full-time job, I mostly develop enterprise applications, working on top of a dozen layers of abstraction. But these foundational components of computing have always kindled my curiosity.

The Plan

I plan to develop a 32-bit instruction set architecture, implement a virtual machine, create an assembly language, and write an assembler for it.

I don't plan to create a complete and comprehensive ISA at first. I will start out with just the loading, storing, and arithmetic instructions. Then, I will write some assembly programs to push the capability of the system. When I hit a wall, I will enhance the ISA and continue. In this way, the ISA will evolve based on the programmer's requirements rather than being the product of a top-down design.

At this point, the system will require a hardware interrupt capability for I/O. Up until now, I will have dumped the content of the registers and memory to see what happened. But now is a good time to provide an 80x24 character display for output, which I will emulate using the native windowing library of the host OS. I will also add keyboard input capability.

I will package the I/O code along with other utility functions into a nice runtime library, which can be used by other programs. This is a good time to provide a linker that can take multiple object files and build them into a single executable file.

The next step is to create a simple high-level language and write a compiler for it. Technically this will be a statically-typed language. But at first, I won't enforce type checking and will allow the program to crash and burn if it wants to. Later on, I may try to implement compile-time type checking.

After that, if I have the time, skill, and patience left, I will try to experiment with a rudimentary file system, a single-tasking OS kernel, and some basic system calls. Things like virtual memory and multi-tasking are quite far away, but worth mentioning here.

The Journey Ahead

Let's be honest. A project of this scale is going to be a messy, chaotic ride. I fully expect to run face-first into architectural dead ends, wrestle with infuriating bugs, and make plenty of boneheaded design choices. There will be setbacks and things will break.

But getting past all of those challenges and making the system work is where the ultimate payoff and satisfaction come from. I plan to document every single step of this journey right here—the breakthroughs, the false starts, and the moments when everything crashes in a ball of virtual smoke.

Whether this project ultimately succeeds, fizzles out, or fails spectacularly, the sheer joy of learning on the bare metal makes every roadblock and dead end entirely worth it.

Let us begin...
